# Глава 2. Три ключевых термина

# xhigh

xhigh — повышенный уровень reasoning effort.

Этот режим нужен, когда важнее качество рассуждения, чем скорость: модель тратит больше
ресурсов на обдумывание, поэтому лучше справляется со сложной проверкой и структурирова­
нием. Цена этого — более высокий расход токенов и обычно более долгий отклик.

# Dynamic Workflows

Dynamic Workflows — JavaScript-сценарий оркестрации субагентов, который Claude пишет и
запускает в фоне.

Практически это выглядит так: Claude сам пишет workflow-скрипт, запускает его в отдельном
рантайме, а вы получаете сводный результат, не теряя основной сессии. Доступны пауза/возоб­
новление, есть лимиты (до 16 агентов одновременно и до 1000 суммарно за запуск), и важно
учитывать повышенный расход токенов. На текущем этапе функция идет как Research Preview и в
Enterprise может регулироваться администратором.

# ultracode

ultracode — режим, который объединяет xhigh и автоматическую workflow-оркестрацию.

В этом режиме Claude для содержательных задач автоматически выбирает workflow-подход и
сочетает его с повышенным уровнем усилия. Режим действует в рамках текущей сессии.

# Глава 3. Для кого это полезно

Эти фичи полезны не только разработчикам. Они особенно полезны там, где задача похожа на
мини-проект:

- много исходных файлов;
- несколько критериев проверки;
- важен финальный артефакт (отчёт, план, редактура), а не «ответ в чат».

Прикладные роли из разборов:

- автор/редактор длинных текстов;
- маркетолог/SEO-специалист;
- аналитик/исследователь;
- руководитель, собирающий action items из заметок и документов;
- специалист с локальной базой знаний (Obsidian/проектные папки).

# Глава 4. Когда включать, а когда
# не включать

# Когда включать

Включайте xhigh / ultracode /workflow, когда есть 3 признака одновременно:

1. Объём: десятки файлов или длинные документы.
1. Параллельность: части задачи можно проверять независимо.
1. Выход: нужен структурированный результат, а не «черновик на глаз».

Примеры:

- аудит большой рукописи по 4 осям (структура, факты, стиль, повторяемость);
- сводка 10+ meeting notes в единый action-plan;
- обзор исследовательской папки с пометкой «подтверждено/спорно».

# Когда не включать

Не включайте, когда задача короткая и линейная:

- правка 1-2 абзацев;
- одно письмо;
- быстрый перевод;
- вопрос «объясни термин».

Для таких задач workflow обычно создаёт лишние задержку и расход.

# Глава 5. Как включить эти
# режимы (пошагово)

Команды и подсказки ниже описаны для Claude Code в терминале и расширения VS
Code — у них общий набор слэш-команд. Чем отличается десктоп-приложение — собрано в
разделе 5.7.

# 5.1. Что нужно иметь до старта

- Claude Code версии v2.1.154 или новее. На более старых версиях режимов просто нет.
- Модель. Сами Dynamic Workflows запускаются на модели вашей текущей сессии — отдельно

Opus 4.8 для них не требуется. А вот режим ultracode работает только на моделях с под­

держкой усилия xhigh (на сегодня это Opus 4.8 ), так что для сценария «включил и забыл»
удобнее всего именно она.
- Платный план. Доступ отличается по тарифам:

| План | Dynamic Workflows |
| --- | --- |
| Max, Team | Включены по умолчанию |
| Pro | Включаются вручную: команда /config → строка «Dynamic workflows» |
| Enterprise | Доступны, но выключены, пока не включит ад­ министратор |

Работает в терминале (CLI), десктоп-приложении и расширении для VS Code.

Важно: функция в статусе Research Preview («исследовательское превью»). Часть деталей
интерфейса ниже описана по первым разборам и может слегка меняться от версии к
версии.

# 5.2. Включаем xhigh (уровень «думать дольше»)

xhigh — это уровень усилия между high и max . Любой из способов:

- Команда: напишите /effort xhigh .
- Слайдер: напишите просто /effort — откроется ползунок уровней, двигайте стрелками.

Шкала обозначается так: ○ low , ◐ medium , ● high , ★ xhigh , ★★ max .
- При запуске из терминала: флаг --effort xhigh .

# 5.3. Включаем ultracode (xhigh + автономия)

ultracode = xhigh плюс право Claude самому решать, когда разворачивать параллельную
бригаду агентов.

- Команда: /effort ultracode .
- Слайдер: в том же меню
/effort это крайний правый пункт с пометкой «xhigh +
workflows».

Как понять, что включилось: при наведении на ultracode по интерфейсу проходит ярко-
фиолетовая пульсация. Дальше Claude сам оценивает каждый запрос и решает: справиться
обычным ответом или собрать воркфлоу. Один ваш запрос в этом режиме может породить це­
почку: проанализировать → внести правки → проверить. Настройка действует в рамках текущей
сессии.

# 5.4. Запускаем Dynamic Workflow вручную (без ultracode )

Воркфлоу не обязательно отдавать на откуп автонастройке — его можно вызвать точечно:

- Слово-триггер: добавьте workflow в запрос («Запусти workflow для аудита этих докумен­
тов»). В терминале это слово подсветится радужным цветом — значит, распознано как
триггер.
- Готовый воркфлоу: /deep-research [ваш вопрос] — параллельный поиск по многим источ­
никам со сборкой отчёта с цитатами.
- Свой воркфлоу: дайте запрос со словом workflow — Claude напишет скрипт; затем введи­

# Глава 7. Риски и ограничения

# Стоимость

Dynamic Workflows расходуют заметно больше токенов, чем обычная сессия.

Практическое правило:

- начинайте с малого объема;
- смотрите план перед запуском;
- масштабируйте только после первой успешной итерации.

# Лишняя параллельность

Больше агентов не равно лучше результат.

Проблема:

- можно получить «дорогую суету» вместо полезного ускорения.

Практическое правило:

- сначала сделать компактный пилот;
- затем постепенно увеличивать масштаб.

# Потеря прозрачности

В workflow-подходе часть промежуточных шагов менее очевидна, чем в ручном пошаговом
режиме.

Практическое правило:

- фиксируйте критерии качества заранее;
- требуйте структурированный итог;
- оставляйте контрольные точки.

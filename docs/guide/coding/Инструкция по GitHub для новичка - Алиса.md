# Привет! Вот подробная пошаговая инструкция для новичка, как разместить проект с локального ПК на GitHub.

---

## Шаг 1. Подготовка проекта на компьютере

1. **Убедись, что проект лежит в отдельной папке.** Например, `my-project`.
2. **Исключи лишнее.** Не загружай временные файлы, кэш, зависимости и т. п. Для этого в корне проекта создай файл `.gitignore` и добавь туда стандартные шаблоны.

Пример `.gitignore` для твоего стека (Vite, Tauri, JS и т. д.):
```gitignore
# Node.js
node_modules/
npm-debug.log
yarn-lock

# Vite
.vite/
dist/

# Tauri
tauri/target/
tauri/icons/

# IDE
.idea/
.vscode/
*.swp

# ОС
.DS_Store
Thumbs.db

# Прочее
*.log
.env
```

3. **Проверь, нет ли в проекте чувствительных данных** (пароли, ключи API, токены). Их лучше не выкладывать вообще.

---

## Шаг 2. Инициализация Git в проекте

Открой терминал в папке проекта (`my-project`) и выполни:

```bash
git init
```

Теперь папка стала Git-репозиторием.

---

## Шаг 3. Добавление файлов в индекс и первый коммит

1. Добавь все файлы под контроль версий:
   ```bash
   git add .
   ```
2. Сделай первый коммит (сохранение версии):
   ```bash
   git commit -m "Initial commit"
   ```

> Коммит фиксирует состояние проекта. Сообщение после `-m` — это краткое описание изменений.

---

## Шаг 4. Создание репозитория на GitHub

1. Зайди на GitHub и войди в аккаунт.
2. Справа сверху нажми **«+»** → **«New repository»**.
3. Заполни поля:
   * **Repository name**: имя проекта (например, `my-project`). Лучше без пробелов, можно использовать дефисы.
   * **Description**: короткое описание (необязательно).
   * **Public/Private**: если хочешь, чтобы другие видели код — выбери **Public**. Если только для себя — Private.
   * Галочку **Add a README file**, **.gitignore** или **License** пока не ставь: у тебя уже есть свои файлы.
4. Нажми **«Create repository»**.

---

## Шаг 5. Связывание локального репозитория с GitHub

На странице созданного репозитория ты увидишь URL вида:
* HTTPS: `https://github.com/username/my-project.git`
* SSH: `git@github.com:username/my-project.git`

Для новичка проще HTTPS. Выполни в терминале в папке проекта:

```bash
git remote add origin https://github.com/username/my-project.git
```
(замени `username` и `my-project` на свои значения).

Проверь, что связь установлена:
```bash
git remote -v
```
Должны отобразиться строки с `origin`.

---

## Шаг 6. Отправка кода на GitHub

Выполни:
```bash
git push -u origin main
```

> Если у тебя ветка называется `master` вместо `main`, используй `git push -u origin master`.

Флаг `-u` связывает локальную ветку с удалённой, чтобы в будущем можно было писать просто `git push`.

Если попросят логин и пароль:
* При HTTPS GitHub обычно предлагает ввести **Personal Access Token** вместо пароля. Его создают в настройках аккаунта GitHub (Settings → Developer settings → Personal access tokens).

---

## Шаг 7. Проверка результата

Зайди на страницу своего репозитория на GitHub. Ты должен увидеть:
* файлы проекта;
* последний коммит с сообщением «Initial commit»;
* кнопку «Code» с ссылкой на репозиторий.

---

## Как дальше обновлять проект (базовый цикл)

Когда ты делаешь изменения в проекте:

1. Добавляешь/меняешь файлы.
2. Фиксируешь изменения:
   ```bash
   git add .
   git commit -m "Что ты сделал, кратко"
   ```
3. Отправляешь на GitHub:
   ```bash
   git push
   ```

## Частые проблемы и советы

* **Ошибка «fatal: refusing to merge unrelated histories» или проблемы с ветками** — чаще всего из‑за того, что на GitHub создали README/gitignore, а локально этого нет. В твоём случае мы не создавали их на GitHub, так что этого не будет.
* **Файл случайно попал в репозиторий** (например, `.env` или `node_modules`):
  1. Добавь его в `.gitignore`.
  2. Удали из Git, но оставь на диске:
     ```bash
     git rm --cached .env
     ```
  3. Закоммить и отправь изменения.
* **Слишком большой репозиторий**: не загружай большие бинарные файлы, дистрибутивы, тяжёлые медиа.

Отвечу как инженер DevOps и преподаватель Git, много лет обучающий разработчиков работе с Git и GitHub с нуля.

Если освоить всего **20% возможностей Git**, то вы будете уверенно решать **95% повседневных задач**. Ниже именно такая инструкция — без перегрузки теорией.

---

# Что такое Git и GitHub

Очень многие их путают.

**Git** — программа, которая хранит историю изменений проекта на вашем компьютере.

**GitHub** — сайт, где можно хранить Git-репозитории, делать резервные копии и работать совместно.

Представьте:

```
Ваш проект
      │
      ▼
Git (история изменений)
      │
      ▼
GitHub (облако)
```

```
git version 2.48.1
```

# Первоначальная настройка Git

Делается один раз.

```bash

```

```bash

```

```bash

```

# Предположим, у вас есть проект

Например

```
MyProject/

    index.html
    app.py
    README.md
```

```
C:\Projects\MyProject
```

# Шаг 1. Инициализировать Git

```bash
git init
```

Появится скрытая папка

```
.git
```

Именно она хранит всю историю проекта.

---

# Шаг 2. Проверить статус

```bash
git status
```

Вы увидите примерно

```
Untracked files:

index.html
main.py
README.md
```

Git сообщает:

> "Я вижу файлы, но пока не слежу за ними."

---

# Шаг 3. Создать .gitignore

Очень важно.

Создаем файл

```
.gitignore
```

Например:

```
node_modules/

.env

venv/

.idea/

.vscode/

__pycache__/

*.log

dist/

build/
```

Секреты, пароли и временные файлы никогда не должны попадать в GitHub.

---

# Шаг 4. Добавить файлы

Добавить всё:

```bash
git add .
```

или конкретный файл

```bash
git add app.py
```

Теперь Git знает:

> Эти изменения я хочу сохранить.

---

# Шаг 5. Создать первый коммит

Коммит — это снимок проекта.

```bash
git commit -m "Initial commit"
```

Получится примерно

```
[main]
Initial commit
```

Поздравляю.

Теперь история проекта уже существует.

---

# Что происходит внутри

Допустим:

```
Версия 1

index.html
app.py
```

Вы изменили код.

Создали второй коммит.

Получится

```
Commit 1

↓

Commit 2

↓

Commit 3
```

Git умеет возвращаться к любой версии.



```

```


# Подключаем GitHub

GitHub покажет команды.

Например

```bash
git remote add origin https://github.com/username/MyProject.git
```

Проверить

```bash
git remote -v
```

Получится

```
origin
```

---

# Отправляем проект

Первый раз

```bash
git branch -M main
```

потом

```bash
git push -u origin main
```

GitHub попросит авторизацию.

После этого проект появится на сайте.

# Самые полезные команды

Посмотреть статус

```bash
git status
```

История

```bash
git log --oneline
```

Все ветки

```bash
git branch
```

Создать ветку

```bash
git branch feature/login
```

Перейти

```bash
git switch feature/login
```

или

```bash
git checkout feature/login
```

Вернуться

```bash
git switch main
```

# Как работать с версиями

Допустим

```
v1
```

Работает отлично.

Вы начали новую функцию.

Лучше создать ветку

```
main

└── feature-chat
```

Работаете там.

Когда всё готово

```
Merge
```

в

```
main
```

Так вы никогда не ломаете рабочую версию.

Git его восстановит.

Посмотреть историю



Пока не сделали commit

```bash

```

Все изменения исчезнут.

Будьте осторожны.

## Несколько советов из практики

* Делайте небольшие коммиты. Лучше 10 понятных коммитов, чем один огромный.
* Коммитьте завершенные логические изменения (например, "добавил авторизацию"), а не каждые две минуты.
* Перед началом работы над новой задачей выполняйте `git pull`, если работаете с удаленным репозиторием.
* Если экспериментируете с новой функциональностью — создавайте отдельную ветку.
* Не бойтесь Git: почти любую ошибку можно исправить, если изменения уже находятся в истории репозитория.

Если вы только начинаете, рекомендую сначала освоить именно этот минимальный набор команд:

```bash
git init
git status
git add .
git commit -m "..."
git log --oneline
git remote add origin <URL_репозитория>
git push -u origin main
git pull
```

Этого достаточно, чтобы комфортно вести собственные проекты. Позже можно переходить к более продвинутым возможностям: веткам, Pull Request, разрешению конфликтов, тегам и интерактивному `rebase`.

# Профессиональный Промпт для ИИ-Кодера (Настройка персонального узла: 3X-UI + WARP)

Этот файл — техническая инструкция. Отправьте её вашему ИИ-кодеру (Anthropic Claude через терминал, Antigravity, Cursor, Cline и др.), предоставив ему ваши данные сервера.

---

### Текст для ИИ-Кодера:

Привет! Твоя задача — полностью настроить приватный узел связи на чистом VPS сервере (Ubuntu). Мы делаем персональное решение с точечной маршрутизацией через Cloudflare WARP для повышения приватности и устранения региональных лимитов.

**Учетные данные сервера:**
- IP: [ВСТАВЬТЕ IP ВАШЕГО СЕРВЕРА]
- User: root
- Password: [ВСТАВЬТЕ ПАРОЛЬ ОТ VPS]

**Сайты и мессенджеры, которые нужно пустить через алгоритм WARP:**
[ЗДЕСЬ НАПИШИТЕ ВАШ СПИСОК: например, ChatGPT, Gemini, Telegram, Instagram...]

**Технические шаги для агента (выполнять строго последовательно):**

1. **Базовая настройка:**
   - Подключись по SSH. Выполни `apt update`.

2. **Установка 3X-UI:**
   - Установи панель 3X-UI через официальный скрипт (`bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)`). Сконфигурируй автоматическую установку без интерактивных вопросов (пользователь `admin`, порт `54321`).

3. **Создание Inbound-точки (VLESS-Reality):**
   - Во встроенной БД панели (`/etc/x-ui/x-ui.db`) создай Inbound-подключение:
     - Протокол: `vless`, Port: `443`, Security: `reality`, Target & ServerNames: `dl.google.com`.
     - Сгенерируй надежные ShortId и PrivateKey для маскировки Reality.
   - **КРИТИЧЕСКИ ВАЖНО:** Обязательно включи параметр `sniffing` в настройках Inbound (`enabled: true`, `routeOnly: true`, destOverride: `["http", "tls", "quic", "fakedns"]`). Из-за отсутствия этого параметра точечная маршрутизация WARP работать не будет, так как пакеты не будут распознавать доменные имена!

4. **Генерация профиля Cloudflare WARP (wgcf):**
   - Скачай `wgcf` (linux-amd64). Выполни команды: `wgcf register --accept-tos` и `wgcf generate`.
   - Из полученного профиля конфигурации извлеки: `PrivateKey`, `Address` (оба - IPv4 и IPv6 адреса), `PublicKey` и `Endpoint` (при сборке JSON используй надежный IP `162.159.192.1:2408`).

5. **Настройка WARP Outbound (x-ui.db):**
   - В БД панели (таблица `settings`) найди параметр `xrayTemplateConfig`.
   - Добавь Outbound с параметрами (protocol: `wireguard`, tag: `warp`).
   - Укажи извлеченные данные: `secretKey`, `address`, `peers` (внутри peers - `publicKey`, `endpoint`, `keepAlive: 15`).
   - **КРИТИЧЕСКИ ВАЖНО:** Во избежание фатальных ошибок модулей ядра на виртуальных серверах, обязательно пропиши `"noKernelTun": true` (gVisor) и `"mtu": 1280` внутри настроек wireguard-протокола.

6. **Настройка Точечной Маршрутизации (Split Tunneling):**
   - Внимательно изучи список пользовательских ресурсов (указан клиентом в начале промпта).
   - Транслируй их в правила Xray (geosite/geoip). Например, если клиент написал Telegram, это преобразуется в `geosite:telegram` и `geoip:telegram`. `Gemini` это `geosite:google` и `domain:gemini.google.com`.
   - В дереве конфигурации `routing.rules` добавь правила: `type: field`, укажи собранные домены и списки IP, и жестко направь их в `"outboundTag": "warp"`.
   - Главная цель: только этот трафик пойдет через Cloudflare, а остальной базовый интернет-серфинг клиент будет осуществлять напрямую через быстрый VPS-канал.

7. **Финализация:**
   - Перезапусти сервис: `systemctl restart x-ui`. Убедись, что нет `IPC error -22` и лог подтверждает запуск: `Using gVisor TUN. NoKernelTun is set to true`.
   - Сформируй и выдай пользователю финальную защищенную ссылку вида `vless://...`. Коротко объясни, как импортировать её в современные кроссплатформенные клиенты (например: универсальный Hiddify для всех ОС, NekoBox/v2rayN для Windows/Linux/macOS, v2rayNG для Android или V2Ray Tun/FoXray для iOS).
